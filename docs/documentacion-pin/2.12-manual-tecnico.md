## Instalación del sistema

Requisitos previos: Node.js instalado, una base PostgreSQL accesible (Supabase o local).

```bash
git clone https://github.com/benjamincarnero1213-cmyk/Patamatch.git
cd Patamatch
npm install
```

## Configuración

Crear un archivo `.env` en la raíz con:

```
DATABASE_URL=postgres://usuario:password@host:puerto/basededatos
JWT_SECRET=una-clave-secreta-larga-y-aleatoria
PORT=3000
```

`DATABASE_URL` y `JWT_SECRET` nunca deben subirse al repositorio (`.env` ya está en
`.gitignore`). Al arrancar por primera vez con una base vacía, el sistema crea las
tablas automáticamente y las siembra con datos de ejemplo (ver 2.11).

**Levantar en local:**
```bash
npm run dev     # con recarga automática
npm start        # modo normal
```

Servidor disponible en `http://localhost:3000`. Cuentas de prueba ya sembradas:
`demo@patamatch.com` / `david@patamatch.com` / `sarah@patamatch.com`, contraseña
`demo123` para las tres.

**Despliegue en producción:** configurado para Vercel vía `vercel.json` — el backend se
despliega como función serverless y el frontend como sitio estático, con `/api/*`
enrutado al backend. Las variables de entorno se configuran en el panel de Vercel, no en
un archivo.

## Estructura del código

```
backend/
  server.js          → entrypoint, define middlewares y monta las rutas
  db/database.js      → conexión a PostgreSQL, esquema y datos semilla
  middleware/
    auth.js            → requireAuth / optionalAuth (verificación de JWT)
    sanitize.js         → sanitización contra XSS
  routes/
    auth.js, pets.js, lost-pets.js, posts.js, stories.js,
    favorites.js, carnets.js, chats.js, notifications.js
frontend/
  index.html
  js/api.js           → cliente HTTP centralizado hacia /api
  js/pages/            → un archivo JS por sección (adoptar, mascotas-perdidas,
                          comunidad, historias, carnet, chats, perfil, login, registro)
```

Cada archivo de `routes/` sigue el mismo patrón: Express Router, funciones `async`, y
respuestas JSON con la forma `{ success: true/false, data/error }`.

## Consideraciones para mantenimiento

- El pool de conexiones a PostgreSQL está limitado a 5 conexiones concurrentes — subirlo
  si el tráfico de demo lo justifica.
- No hay *rate limiting* en los endpoints públicos (`GET /api/pets`, `GET /api/lost-pets`)
  — agregar si se expone la demo públicamente por tiempo prolongado.
- Las columnas `marker_top`/`marker_left` de `lost_pets` guardan coordenadas reales bajo
  un nombre heredado — ver nota en 2.11 antes de tocar la lógica de mapas o alertas.
- El README.md que se había agregado el 11 de junio (commit `95104ba`) ya no existe en
  el repositorio — recrearlo con, como mínimo, esta sección de instalación.
- Cuando se integre el proveedor de IA (2.10), documentar acá el costo por uso y el
  límite de requests para no generar sorpresas de facturación.
